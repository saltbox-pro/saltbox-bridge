## Описание

Компонент Bridge – набор дополнительных модулей SaltStack, подключающих
мастер Salt к Salt.Box

Поддерживаемые на данный момент версии salt-master:
- 3007.13

## Иерархия файлов Salt

- `/srv/salt_custom/` – для пользовательских файлов, управляемых через Salt.Box
  File Browser
- `/srv/saltbox_salt/` – часть системы Salt.Box для репликации состояний из
  пакетов
- `/srv/salt_local/` – для локальных состояний и модулей Salt.Box
- `/srv/salt_master_local/` – для состояний и модулей локального миньона
  сервиса Salt.Box на мастере
- `/srv/salt_extmod/` – для «внешних модулей». Часть из них поставляется
  вместе с этим репозиторием, сюда же можно добавлять свои
- `/srv/sshfs/` – для файлов, которые отдаются одновременно как `ssh://` и
  как `salt://`
- `/srv/migrator/` – каталог файлов Salt, связанных с процессом миграции,
  доступен через filebrowser при включённом флаге
  `FILEBROWSER_MIGRATOR_SOURCE_ENABLED`

## Установка вторичного Salt Master

Скрипт [`bin/install_master.sh`](./bin/install_master.sh) устанавливает Salt
и подключает новый, независимый `salt-master` к SaltBox через Redis.
Используйте его, чтобы подключить мастер, работающий на отдельном хосте, так
чтобы он делился данными о job-ах с основным инстансом SaltBox, при этом
миньон этого хоста не управляется мастером SaltBox.

Полное ручное, шаг за шагом, описание того же процесса смотрите в
[пользовательской документации Salt.Box](https://saltbox.pro/docs/next/administration/master_install).

### Требования

- Хост с сетевым доступом к инстансу Redis SaltBox по **IP-адресу**, имена
  хостов в запросах скрипта не принимаются, и его порту, `6379` по умолчанию
- Сертификат удостоверяющего центра `redis-ca.crt`, выпущенный инстансом
  SaltBox. Получить его со стороны SaltBox можно через
  [Salt.Box Compose](https://dev.saltbox.pro/saltbox/saltbox-compose),
  например:

  ```bash
  sudo ./bin/sb-compose.sh cp redis-salt:/etc/redis/certs/ca.crt ./redis-ca.crt
  ```

> **ВНИМАНИЕ!** Скрипт нужно запускать от root. Он устанавливает системные
> пакеты, пишет в `/etc/salt/`, `/etc/apt/` и включает systemd-сервис
> `salt-master`

### Быстрый старт

Скрипт самодостаточен и может быть скопирован на целевой хост сам по себе:
он самостоятельно клонирует остальной `saltbox-bridge` в каталог
`saltbox-bridge/` рядом со своим расположением.

```bash
sudo ./bin/install_master.sh
```

Используйте `--en_locale` или `--ru_locale`, чтобы выбрать язык
интерактивных запросов и сообщений в лог, по умолчанию используется русский.
Используйте `-h`/`--help`, чтобы вывести полный список опций и краткое
описание того, что делает скрипт.

```bash
sudo ./bin/install_master.sh --en_locale
```

### Что делает скрипт

1. Устанавливает сертификат `redis-ca.crt`, автоматически найденный рядом со
   скриптом или указанный по пути, в `/etc/salt/ssl/redis-ca.crt`.
2. Проверяет подключение к инстансу Redis SaltBox по указанному IP-адресу и
   порту
3. Устанавливает необходимые системные пакеты: `curl`, `git`, `rsync`,
   `gettext` и другие
4. Устанавливает Salt из официального APT-репозитория
5. Создаёт каталоги [иерархии файлов Salt](#иерархия-файлов-salt)
6. Клонирует или обновляет репозиторий [`saltbox-bridge`](https://dev.saltbox.pro/saltbox/saltbox-bridge)
   рядом со скриптом
7. Синхронизирует файлы Bridge в каталоги Salt, перечисленные выше, и
   устанавливает Python-пакет Bridge
8. Рендерит `/etc/salt/master`, `/etc/salt/minion` и `/etc/salt/saltbox` из
   файлов шаблонов Bridge [`master/templates/`](./master/templates),
   заполняя их данными подключения к SaltBox
9. Включает и перезапускает сервис `salt-master`
10. Отключает `salt-minion`, поскольку у вторичного мастера нет своего
    миньона

### Интерактивные запросы

Во время работы у вас спросят:

- сертификат `redis-ca.crt`: либо позволить скрипту найти его автоматически
  в текущем каталоге, либо указать путь
- IP-адрес SaltBox и порт Redis
- ID Salt master, по умолчанию `master-<timestamp>`, и уровень логирования
  для мастера и миньона, задаются раздельно по шкале `0`–`9`, см.
  [уровни логирования Salt](https://docs.saltproject.io/en/latest/ref/configuration/logging/index.html),
  по умолчанию `1`/`info`
- имя пользователя Redis, по умолчанию `redis`, и пароль, используемые в
  конфиге `saltbox`

> **ПРИМЕЧАНИЕ:** Если локальная копия `saltbox-bridge` уже существует рядом
> со скриптом, вас спросят, использовать её повторно или переклонировать.
> Переклонирование **НАВСЕГДА УДАЛЯЕТ** локальную копию, о чём вас отдельно
> предупредят, если в ней есть незакоммиченные изменения

### Повторный запуск скрипта

**Скрипт безопасно запускать повторно**: установка пакетов и создание
каталогов идемпотентны, а конфиги каждый раз полностью перерендериваются из
шаблонов Bridge.

Повторный запуск – **рекомендуемый** способ подхватить обновлённые шаблоны
Bridge или изменить ID мастера, уровни логирования или учётные данные Redis.

## Подключение существующего Salt Master

Скрипт [`bin/adopt_existing_master.py`](./bin/adopt_existing_master.py)
подключает к SaltBox уже работающий `salt-master` со своим собственным
конфигом и миньонами, добавляя в его конфиг только настройки, нужные Bridge,
вместо полной замены конфига мастера. Он рассчитан на запуск из
bootstrap-инсталлятора Salt.Box, а не на запуск вручную, поскольку ожидает,
что рядом уже существует локальная копия SaltBox Compose.

### Требования

- Доступ root на хосте, где уже работает подключаемый `salt-master`
- Локальная копия `saltbox-compose` в каталоге, переданном в
  `--saltbox-dir`, используется для чтения параметров подключения к Redis и
  CA-сертификата
- Установленный PyYAML для интерпретатора Python, которым запускается скрипт

### Использование

```bash
sudo python3 ./bin/adopt_existing_master.py \
  --release-tag RELEASE_TAG \
  --master-bin /etc/salt/master \
  --saltbox-dir /path/to/saltbox
```

- `--release-tag`: релиз `saltbox-bridge`, из которого скачиваются и
  устанавливаются файлы Bridge
- `--master-bin`: путь к существующему конфигу Salt master, который нужно
  подключить
- `--saltbox-dir`: каталог с копией `saltbox-compose`, из которой читаются
  параметры подключения
- `--master-id`: ID Salt Master, по умолчанию генерируется автоматически.
  Уже настроенный `salt_box_master_id` в `/etc/salt/saltbox` всегда имеет
  приоритет
- `--ignore-version-check`, `--debug`: опциональные флаги

### Что делает скрипт

1. Читает параметры подключения к Redis, хост, порт, имя пользователя,
   секрет с паролем, из локальной копии `saltbox-compose`
2. Ждёт, пока инстанс Redis станет доступен
3. Создаёт резервную копию существующего конфига `/etc/salt/master` с
   отметкой времени
4. Скачивает архив релиза `saltbox-bridge` для указанного тега,
   устанавливает Python-пакет Bridge и синхронизирует файлы Bridge в
   каталоги Salt
5. Определяет ID Salt Master, используя уже настроенный в
   `/etc/salt/saltbox`, если он есть
6. Добавляет в существующий конфиг мастера только настройки, нужные Bridge,
   вместо того чтобы перезаписывать его целиком
7. Копирует CA-сертификат Redis и записывает `/etc/salt/saltbox` с
   параметрами подключения
8. Включает и перезапускает сервис `salt-master`

## Установка Salt Evil Minions

Скрипт [`bin/install_evil.sh`](./bin/install_evil.sh) устанавливает и
запускает [Salt Evil Minions](https://dev.saltbox.pro/saltbox/saltbox-evil-minions) –
настраиваемое количество evil-миньонов, подключающихся к настоящему
`salt-master`.

Скрипт не зависит от `install_master.sh` и не клонирует и не устанавливает
`saltbox-bridge`: ему нужен только уже установленный на хосте Salt onedir
runtime.

### Требования

- Уже установленный Salt onedir runtime по пути
  `/opt/saltstack/salt/bin/python3`, например через `install_master.sh`, или
  обычный пакет `salt-minion`/`salt-master`
- **IP-адрес** целевого мастера, доступный с этого хоста по портам
  `4505`/`4506`

> **ВНИМАНИЕ!** Скрипт нужно запускать от root. Он пишет в
> `/etc/salt/minion.d/`, `/etc/systemd/system/`, `/etc/evil-minions.env` и
> включает systemd-юниты `evil-minions` и `evil-minions-restart.timer`

### Быстрый старт

```bash
sudo ./bin/install_evil.sh
```

Используйте `--en_locale` или `--ru_locale`, чтобы выбрать язык
интерактивных запросов и сообщений в лог, по умолчанию используется русский.
Используйте `-h`/`--help`, чтобы вывести полный список опций и краткое
описание того, что делает скрипт.

```bash
sudo ./bin/install_evil.sh --en_locale
```

### Что делает скрипт

1. Проверяет, что Salt onedir runtime присутствует по пути
   `/opt/saltstack/salt/bin/python3`
2. Спрашивает, к какому IP-адресу мастера должны подключаться evil-миньоны и
   сколько их запустить
3. Записывает оверрайды `/etc/salt/minion.d/master.conf` и
   `/etc/salt/minion.d/waiting.conf`
4. Клонирует репозиторий [`saltbox-evil-minions`](https://dev.saltbox.pro/saltbox/saltbox-evil-minions)
   в `/opt/saltstack/evil-minions`
5. Устанавливает его systemd-юниты, `evil-minions.service`,
   `evil-minions-restart.service` и `evil-minions-restart.timer`, и его файл
   окружения `/etc/evil-minions.env`
6. Спрашивает уровень логирования evil-minions
7. Включает и перезапускает сервисы `evil-minions` и
   `evil-minions-restart.timer`

### Интерактивные запросы

Во время работы у вас спросят:

- целевой адрес мастера: либо локальный мастер на этом хосте, `127.0.0.1`,
  либо произвольный **IP-адрес**
- количество evil-миньонов для запуска, по умолчанию `100`
- уровень логирования evil-minions по шкале `1`-`5`, `INFO`, `WARNING`,
  `ERROR`, `CRITICAL` или `DEBUG`, по умолчанию `1`/`INFO`

> **ПРИМЕЧАНИЕ:** при повторном запуске скрипт переклонирует
> `saltbox-evil-minions`, удаляя локальную копию, и перерендеривает
> оверрайды миньона, systemd-юниты и файл окружения
